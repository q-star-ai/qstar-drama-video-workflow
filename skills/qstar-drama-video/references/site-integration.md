# 现有短剧站点接入任务

本文件是给站点实现者的工作清单。依据本机发现的旧 Go 服务和网页快照编写；两份快照尚未被证明是现网权威源码。开始修改前先确认站点仓库、部署 commit 与数据库版本。

1. 对照当前站点的数据结构，复用剧本、分镜、角色、场景、素材和 VideoGeneration 记录；补入 `input_mode`、资产版本/校验值、实际 provider、fallback 事件、GPU 费用、输出探测及质检状态。
2. 服务端 provider 能力表必须驱动前端表单与提交校验。不能让 UI 选中 H3 不支持的输入组合。旧网页若仍将 `provider` 写死为 `doubao`，改成服务端返回候选链；安全提示词重试与供应商切换分开记录。
3. 现有 Go `generateVideoWithFailover` 可保留上游提交错误的分类，但补齐异步任务失败后的恢复/切换策略。已得到外部任务 ID 时，先查询原任务，不自动重复提交。将 H3 作为新的适配器接入同一 Job 状态机；H3 的启动/提交/下载/关闭交由隔离 worker，不在 Web 请求中阻塞。
4. H3 worker 通过队列读取任务，凭证保存在工作端的受限配置中；网站和浏览器不接收密钥。实例启动、停机、成本上限、取消和超时要可观察。只有拥有该实例的任务且无其他运行任务时才自动停机。
5. 输出入统一资产存储后运行 `ffprobe`，再进行人物/服装/场景/镜头/声音质检。只有实际成片及质检状态通过，前端才显示完成。
6. 首个端到端样片只用一镜客户批准的参考素材。核对实际 5–10 秒、画幅、脸、衣服、场景、声音、文件可读、费用及停机状态；通过后才扩大到第一集。保活计划任务独立运行，不占用正式视频任务的幂等键。

完成时提交可审查的代码变更、数据库迁移、部署说明及一镜证据。不要把 API Key、客户照片、签名 URL 或生产数据库导出提交到 GitHub。
