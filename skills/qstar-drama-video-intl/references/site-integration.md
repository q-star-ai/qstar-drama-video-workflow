# Existing Short-Drama Site Integration Tasks

> **Overseas execution (API, queue, asset storage, callbacks, playback, keys, billing) is a separate workstream; not configured; do not reuse domestic production data or customer assets.** This file plans the site-side integration. It was written from an old Go service and web snapshots found on this machine; neither snapshot has been proven to be the authoritative live source. Before making changes, confirm the site repository, the deploy commit and the database version.

1. Against the current site's data structures, reuse script, shot, character, set, asset and VideoGeneration records; add `input_mode`, asset version/checksum, actual provider, fallback events, GPU cost, output probing and QC status.
2. The server-side provider capability table must drive the frontend form and submission validation. The UI must not let a user select an input combination H3 does not support. If the old web still hardcodes `provider` as `doubao`, switch it to a server-returned candidate chain; record safe-prompt retries and provider switches separately.
3. The existing Go `generateVideoWithFailover` may keep its upstream error classification, but must complete the resume/switch strategy after an async task fails. Once an external task ID is obtained, query the original task first instead of auto re-submitting. Wire H3 in as a new adapter on the same Job state machine; H3's start/submit/download/close are handled by an isolated worker, not blocking inside the web request.
4. The H3 worker reads tasks over a queue; credentials live in a restricted config on the worker; the site and browser never receive keys. Instance start, shutdown, cost ceiling, cancellation and timeout must be observable. Auto-shutdown only when the task owning that instance has no other running task.
5. After output lands in unified asset storage, run `ffprobe`, then QC face/wardrobe/set/camera/audio. Only when the actual clip and QC status pass does the frontend show completion.
6. The first end-to-end sample uses only one shot of customer-approved reference material. Verify actual 5–10 seconds, aspect ratio, face, wardrobe, set, audio, file readability, cost and shutdown status; expand to the first episode only after passing. The keep-alive scheduled task runs independently and does not consume the idempotency key of a real video task.

On completion, submit reviewable code changes, database migrations, deploy notes and one-shot evidence. Do not commit API keys, customer photos, signed URLs or production database exports to GitHub.
